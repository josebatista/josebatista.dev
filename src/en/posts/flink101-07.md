In the previous post, we split a workload into parts that can be executed by different instances. When those instances live in different processes or nodes, a simple consequence appears: one process cannot directly access the object that is in another process's memory.

## The problem

A record that exists in memory in one process cannot cross the network as a direct reference. It needs a transportable form:

```mermaid
flowchart LR
    A[Object in memory] --> B[Serialization]
    B --> C[Bytes]
    C --> D[Network]
    D --> E[Bytes]
    E --> F[Deserialization]
    F --> G[Object at the destination]
```

Transforming the object into bytes is serialization. Rebuilding it on the destination is deserialization.

### The same log in another form

In memory, the record can exist as an object with fields and methods. To transport it, it needs a format that the other process can read. If the chosen format were JSON, for example, we could visualize the handoff like this:

```text
Object in memory
LogEvent(service="payment", level="ERROR", duration=1432)

Transportable representation
{"service":"payment","level":"ERROR","duration":1432}
```

JSON is just an example; the actual format can be different and is not always human-readable. The important idea is that processes do not exchange the same object reference; they exchange a representation of the data.

Even if the processes are on the same machine, they still have separate memories and need this conversion. When they are on different nodes, the bytes also travel across the network.

### Size also becomes a cost

This conversion uses CPU, creates allocations, consumes buffers, and defines how many bytes need to be moved. At high volume, different data representations with just a few extra bytes make a difference:

| Representation | Size per record | Volume for 1 million records |
| --- | ---: | ---: |
| A | 50 bytes | approximately 50 MB |
| B | 500 bytes | approximately 500 MB |

The second representation carries ten times more data. This cost appears in the network, memory, buffers, storage, and processing time.

So the choice of representation can make all the difference.

## The idea I want to keep

Distributing work also distributes memory. Whenever data crosses processes or machines, communication becomes part of the system's cost.
