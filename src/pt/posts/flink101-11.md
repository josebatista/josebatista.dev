Com o cluster local em execução, chegou a hora de abrir o Flink pelo lado da aplicação. Mas eu não queria começar copiando um código pronto sem saber onde ele vive.

O primeiro passo foi separar quatro coisas:

- **Projeto Java**: código e dependências
- **Flink Application**: programa que declara uma computação
- **Job**: computação executada pelo cluster
- **cluster**: processos e recursos que executam o Job

## O ambiente

O cluster Flink já está executando no Docker. Para escrever o Job, confirmei Java 21 e Maven:

```bash
java -version
mvn -version
```

O laboratório segue uma organização didática simples:

```text
my-flink-studies/
└── 01-fundamentos/
    └── labs/
        ├── day00/
        │   └── resources/
        │       └── compose.yaml  ← arquivo atual
        └── day03/
            ├── pom.xml
            └── src/
                ├── main/
                │   ├── java/dev/josebatista/flink101/day03/
                │   │   └── FirstDataflowJob.java
                │   └── resources/
                └── test/
                    └── java/dev/josebatista/flink101/day03/
```

O código segue o layout reconhecido automaticamente pelo Maven. O caminho de diretórios corresponde ao package `dev.josebatista.flink101.day03`, enquanto arquivos auxiliares ficam em `src/main/resources`.

## As dependências mínimas

```xml
<properties>
    <maven.compiler.release>21</maven.compiler.release>
    <flink.version>2.2.1</flink.version>
</properties>

<dependencies>
    <dependency>
        <groupId>org.apache.flink</groupId>
        <artifactId>flink-streaming-java</artifactId>
        <version>${flink.version}</version>
        <scope>provided</scope>
    </dependency>
    <dependency>
        <groupId>org.apache.flink</groupId>
        <artifactId>flink-clients</artifactId>
        <version>${flink.version}</version>
        <scope>provided</scope>
    </dependency>
</dependencies>
```

O escopo `provided` existe porque o cluster já fornece as bibliotecas centrais. Quando a aplicação usar bibliotecas adicionais, elas precisarão estar instaladas no cluster ou incluídas no artefato submetido.

## O que existe dentro da classe

Uma aplicação Java começa em `main`:

```java
package dev.josebatista.flink101.day03;

public class FirstDataflowJob {
    public static void main(String[] args) throws Exception {
        StreamExecutionEnvironment env =
            StreamExecutionEnvironment.getExecutionEnvironment();

        // O dataflow será declarado aqui.

        env.execute("day03-first-dataflow");
    }
}
```

Esse trecho ainda não descreve uma computação útil. Ele apenas localiza os elementos antes da prática:

- `main` é o ponto de entrada da Application;
- `StreamExecutionEnvironment` é o contexto usado para declarar/configurar o Job;
- `execute()` finaliza a descrição e solicita sua execução.

No próximo post, vou preencher o espaço entre o environment e `execute()`.

## Build e submissão

Build e execução são etapas diferentes.

O Maven gera o JAR:

```bash
mvn -f 01-fundamentos/labs/day03/pom.xml clean package
```

Depois, o client Flink do JobManager submete esse JAR:

```bash
docker compose -f 01-fundamentos/labs/day00/resources/compose.yaml exec jobmanager \
  ./bin/flink run /workspace/01-fundamentos/labs/day03/target/flink101-day03-1.0-SNAPSHOT.jar
```
